# Задачи по деплою на amvera.ru

Разбивка плана с разделением: [Агент] / [Пользователь]

## Этап 1. Подготовка файлов для деплоя
- [ ] **[Агент]** Создать `amvera.yaml` в корне репозитория
  - meta environment: docker
  - build.dockerfile: calendar-of-meetings/Dockerfile (или перенести Dockerfile в корень)
  - run.containerPort: 4000
  - run.persistenceMount: /app/data
- [ ] **[Агент]** Проанализировать и при необходимости скорректировать `Dockerfile` под контекст сборки из корня репозитория (если `build.dockerfile` указывает на файл в подпапке)
- [ ] **[Агент]** Убедиться, что `Dockerfile`, `.dockerignore`, `docker-entrypoint.sh` готовы для использования Amvera
- [ ] **[Агент]** Проверить наличие всех нужных файлов в git (рекомендуется добавить: `Dockerfile`, `.dockerignore`, `docker-entrypoint.sh`, `docker-compose.yml`, `amvera.yaml`)

## Этап 2. Подготовка репозитория
- [ ] **[Пользователь]** Закоммитить и запушить файлы в Git репозиторий (GitHub/GitLab/Bitbucket или Amvera Git)
- [ ] **[Пользователь]** Убедиться, что в репозитории есть доступ для Amvera

## Этап 3. Настройка в Amvera
- [ ] **[Пользователь]** Создать приложение в панели amvera.ru из Git-репозитория
- [ ] **[Пользователь]** Проверить, что Amvera подхватил `amvera.yaml`
- [ ] **[Пользователь]** Настроить сборку по Dockerfile (путь из amvera.yaml)
- [ ] **[Пользователь]** Настроить переменные окружения:
  - `NODE_ENV=production`
  - `PORT=4000`
  - `MEETINGS_DB_PATH=/app/data/meetings.sqlite`
  - `AUTH_DISABLED=1` (уже в Dockerfile, можно добавить явно)
- [ ] **[Пользователь]** Создать и примонтировать постоянный том в путь `/app/data` (Persistent Volume)

## Этап 4. Деплой и проверка
- [ ] **[Пользователь]** Запустить деплой в Amvera
- [ ] **[Агент]** При наличии проблем в логах сборки/запуска - помочь с диагностикой и правками
- [ ] **[Пользователь]** Проверить работоспособность: открыть домен, проверить `/api/me`
- [ ] **[Пользователь]** Протестировать сохранение данных (создать встречу, перезапустить/передеплоить приложение)

## Этап 5. Финализация (опционально)
- [ ] **[Пользователь]** При необходимости отключить `AUTH_DISABLED` и настроить реальные пароли/`SESSION_SECRET`
- [ ] **[Пользователь]** Подключить кастомный домен и проверить HTTPS

## Примечания
- `docker-compose.yml` не используется Amvera - только для локальной проверки
- В образе уже добавлен `AUTH_DISABLED=1` по умолчанию - требование для проверки внешней системой выполнено
- SQLite требует Persistent Volume в `/app/data`
- Amvera автоматически выдаст HTTPS сертификат
- Если Dockerfile лежит в подпапке, важен корректный `build.dockerfile` в `amvera.yaml` и правильный build context
