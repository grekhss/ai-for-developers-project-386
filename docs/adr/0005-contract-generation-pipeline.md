# Пайплайн контракта: SDK клиента и серверные артефакты из одной спеки

ADR-0004 сделал `contract/main.tsp` единым источником и генерировал из него только две TS-копии типов, оставив клиент и `server/validate.ts` рукописными. Решили дорастить пайплайн до **реальных генератов на обе стороны**: клиентский SDK (`@hey-api/openapi-ts@0.95.0` → `src/lib/api-gen/`, рантайм `@hey-api/client-fetch`) и серверные схемы (`@typespec/json-schema@~1.11.0` → `contract/schema/`, валидация через `ajv`), объединив всё в **одну самопроверяющуюся команду** `npm run contract` — она генерирует артефакты и тут же сверяет их повторной генерацией во временный каталог. Границы сохраняются: `ajv` проверяет только формат (булев предикат), русские тексты ошибок и условное `bookerName`-только-для-гостя остаются рукописными в роутах.

## Considered Options

- **Только типы (границы ADR-0004)** — минимум тулчейна, но клиент и валидация остаются рукописными, а «единая команда» порождает лишь типы. Отклонено: не покрывает цель «одной командой генерировать спеку, SDK и серверные артефакты».
- **`openapi-fetch` + рукописный `validate.ts`** — тонкий клиент без кодогенерации; отклонено вместе с предыдущим как недостаточное.
- **Гибрид (генерат только на сервер)** — отклонено: выбраны генераты на обе стороны.

## Consequences

- **Пины под Node 20.** `@hey-api/openapi-ts@0.95.0` — последняя линия под Node ≥20.19 (`0.96+` требует ≥22); `@typespec/json-schema@~1.11.0` (эмиттер `1.17` требует compiler `^1.17`). Обновление — только вместе с апгрейдом Node.
- **Единая команда самопроверяется.** `npm run contract` = генерация всех семейств + перегенерация во временный каталог и `diff`; `contract:check` остаётся side-effect-free и живёт внутри `npm run check`. Новый генератор обязан добавить ступень и в генерацию, и в `check`.
- **Генерат подчиняется нашим правилам.** Каталоги генерата обязаны проходить `oxlint` и `tsc` strict (`verbatimModuleSyntax`, `erasableSyntaxOnly`); при конфликте правим конфиг/исключения, а не генерат.
- **Граница «формат vs роль».** JSON Schema выражает формат; роль-зависимые правила (`bookerName` для гостя) и русские тексты остаются рукописными — риск «тихой» подмены семантики принят явно.
