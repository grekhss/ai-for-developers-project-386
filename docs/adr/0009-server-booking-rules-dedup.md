# Сервер проверяет доменные правила букинга; дублирование в server/ вместо shared/

Изначально ADR-0007 оставлял окно записи, прошедшие даты, выходные и сетку
времени политикой UI: сервер проверял только целостность. Ревью проекта
потребовало проверять правила на сервере (API не должен принимать запись
в прошлом, на выходной или вне допустимого окна). Решили продублировать
правила в `server/booking-rules.ts` — чистые функции с параметром `moment`
('YYYY-MM-DD HH:mm'), без чтения системных часов (T3); часы читает только
роут через `server/date.ts`. Граница слоёв (`rootDir: server`, запрет импорта
`src/`) остаётся нетронутой, `tsconfig.server.json` не меняется — дублирование
шести правил дешевле ввода общего `shared/`-модуля.

## Considered Options

- **Общий `shared/`-модуль, импортируемый и `src/lib`, и `server/`.** —
  отклонено: потребовал бы правок `tsconfig.server.json`/`tsconfig.server.build.json`
  (`rootDir`/`include`) и намеренного изменения документированной границы слоёв
  (ADR-0007) ради небольшого набора чистых функций. Путь роста был записан в
  ADR-0007 как «отдельный тикет», но в текущих условиях дублирование
  (`src/lib/window.ts`, `src/lib/slots.ts` и `server/booking-rules.ts`)
  достаточно.
- **Клиентская проверка остаётся единственной.** — отклонено: сервер,
  принимающий запись в прошлое/выходной/вне окна, некорректен для API;
  кроме того, правила нужно гарантировать вне браузерного клиента.
- **Дублировать правила в `server/booking-rules.ts`** — выбран.

## Consequences

- **Правила в двух местах синхронно:** `src/lib/window.ts` и `src/lib/slots.ts`
  (фронт) и `server/booking-rules.ts` (сервер). Оба набора оперируют
  `'YYYY-MM-DD'` и `moment`, оба покрыты юнит-тестами; расхождение
  границ поймает интеграционный тест (400 с конкретной русской ошибкой).
- **Сервер отклоняет доменные нарушения 400:** прошедшая дата, выходной,
  дата вне окна 14 дней, время вне сетки 09:00–18:00 с шагом 30 минут,
  уже начавшийся сегодняшний слот. Занятость по-прежнему держит
  `UNIQUE(date, time)` → 409.
- **Тест-документация T11 удалена:** намеренное «сервер пропускает
  выходные/внеоконные» больше не закреплено; поведение зафиксировано
  правилами и тестами.
- **ADR-0007 суперседирован.** Синхронизация правил теперь явное
  архитектурное допущение, а не «тикет, который никогда не сделан».
- **Контракт уточнён:** `createMeeting` документирует новые 400; заголовок
  `contract/main.tsp` больше не заявляет, что домен — только политика UI.
