# План подготовки решения для деплоя в облако с помощью Docker

## Цель
Упаковать приложение и его окружение в один образ, который одинаково запускается локально, в CI и в облаке. 
Требование: **обязательно** добавить `AUTH_DISABLED=1` по умолчанию в образ для проверки внешней системой.

## Задачи (разбиты по этапам)

### Задача 1: Подготовка Docker-контекста
- [x] Создать `.dockerignore` в `calendar-of-meetings/` (исключить node_modules, dist, .env, git и др.)
- [x] Убедиться, что `.env.example` содержит необходимые переменные

### Задача 2: Создание многостадийного Dockerfile
- [x] Этап `builder`: установка системных зависимостей для `better-sqlite3`, `npm ci`, копирование исходников + контракта, запуск `npm run build` (contract + tsc + vite + tsc server)
- [x] Этап `runtime`: минимальный образ на `node:20-slim`, `npm ci --omit=dev`, копирование `dist/`, `dist-server/`, `contract/schema/`
- [x] **Критично**: добавить `ENV AUTH_DISABLED=1` в runtime-этап
- [x] Создать `data/` с правами для пользователя `node`, запуск от `node`, `EXPOSE 4000`, `CMD ["node", "dist-server/index.js"]`

### Задача 3: Локальная валидация через docker-compose
- [x] Создать `docker-compose.yml` с `AUTH_DISABLED=1` по умолчанию, томом для `data/meetings.sqlite`, healthcheck
- [x] Проверить сборку: `docker compose up --build`
- [x] Проверить работоспособность: статика отдаётся, API доступен, SPA-fallback работает
- [x] Проверить персистентность БД при перезапуске контейнера

### Задача 4: Подготовка к деплою
- [x] Проверить, что образ корректно работает без `.env` файла (за счёт `AUTH_DISABLED=1` по умолчанию)
- [x] Убедиться, что переменные `ADMIN_PASSWORD`, `GUEST_PASSWORD`, `SESSION_SECRET` при необходимости могут быть переопределены извне
- [x] Подготовить инструкции по монтированию персистентного тома для `data/`

### Задача 5: Выбор облака и деплой (интерактивный шаг)
**Не выполнять автоматически. Обязателен диалог с пользователем.**

Вопросы для пользователя:
1. Какое облако планируется использовать?
   - [ ] Render.com
   - [ ] Railway
   - [ ] Fly.io
   - [ ] Render (альтернативный вариант)
   - [ ] Другое (указать название)

2. Предпочтительный способ деплоя?
   - [ ] Собрать образ локально и запушить в Container Registry (Docker Hub / GHCR)
   - [ ] Дать провайдеру собирать напрямую из Git репозитория по Dockerfile

3. Нужна ли БД вне SQLite? (SQLite файл хранится в томе, на некоторых PaaS эфемерный диск - нужен Persistent Disk)
   - [ ] Да, нужна внешняя БД
   - [ ] Нет, достаточно Persistent Volume

4. Есть ли домен/требования к HTTPS?
   - [ ] Да
   - [ ] Нет

После получения ответов - подготовить пошаговую инструкцию под выбранный вариант с настройкой переменных окружения, тома/диска, порта, healthcheck.

## Результат
Один Docker-образ, содержащий собранное приложение (фронт + бэк), который одинаково запускается:
- локально через `docker run` / `docker compose`
- в CI
- в облаке

Критическое требование выполнено: `AUTH_DISABLED=1` добавлен по умолчанию в образ.
