# Деплой в Amvera Cloud

Amvera.ru - облачная платформа для деплоя контейнеров из Git репозитория.

## 1. Подготовка к деплою

Собранные файлы:
- `Dockerfile` - многостадийный билд, `AUTH_DISABLED=1` по умолчанию
- `.dockerignore` - оптимизация контекста
- `docker-compose.yml` - для локальной проверки

Что нужно добавить в git - эти файлы уже созданы в `calendar-of-meetings/`. Их нужно закоммитить.

## 2. Конфигурация в Amvera

В панели amvera.ru создаём новый проект из Git репозитория.

### Основные настройки

1. **Сборка**: Выбран вариант "Дать провайдеру собирать напрямую из Git репозитория по Dockerfile"
   - Amvera автоматически найдёт `Dockerfile` в `calendar-of-meetings/`
   - Укажите контекст сборки: `calendar-of-meetings/` (если репозиторий не корневой)

2. **Порт**: Приложение слушает на `PORT` из env, по умолчанию `4000`. В Dockerfile `EXPOSE 4000`.
   - В Amvera нужно указать порт `4000`

3. **Переменные окружения**

Обязательные (можно переопределить, даже с AUTH_DISABLED=1):
```env
NODE_ENV=production
PORT=4000
MEETINGS_DB_PATH=/app/data/meetings.sqlite
AUTH_DISABLED=1
```

Если хотите использовать реальную авторизацию (не дев-режим), переопределите:
```env
AUTH_DISABLED=0
ADMIN_PASSWORD=<ваш_пароль>
GUEST_PASSWORD=<ваш_пароль>
SESSION_SECRET=<секретная_строка_минимум_32_символа>
```

Сгенерировать `SESSION_SECRET`: `openssl rand -hex 32`

4. **Persistent Volume (том)**

Для SQLite файла нужен персистентный том, примонтированный в `/app/data`.
- В настройках Amvera создайте диск/volume и примонтируйте его к пути `/app/data`
- Размер зависит от ожидаемого количества встреч (SQLite небольшой)
- Том сохранит `meetings.sqlite` между перезапусками деплоя

## 3. Деплой

1. Push изменений в Git (`Dockerfile`, `.dockerignore`, `docker-compose.yml`, `DEPLOY_PLAN.md`, `DEPLOY_AMVERA.md`)
2. В Amvera подключить репозиторий, выбрать ветку
3. Указать путь к Dockerfile (если нужно) и контекст `calendar-of-meetings/`
4. Настроить порт 4000, переменные окружения, примонтировать volume в `/app/data`
5. Нажать "Deploy"

## 4. Проверка

После деплоя:
- Откройте домен Amvera - должна открыться главная страница календаря
- Проверьте API: `GET https://<your-domain>/api/me` должен вернуть `{"role":"guest","bookerName":"Гость"}` при `AUTH_DISABLED=1`
- Создайте тестовую встречу - после ребилда она должна сохраниться (благодаря volume)

## 5. HTTPS

Amvera автоматически выдаёт SSL-сертификат для домена (Let's Encrypt). Домен можно подключить кастомный или использовать автоматически сгенерированный `.amvera.app`.

## 6. Примечания

- В образе `AUTH_DISABLED=1` по умолчанию - это требование для проверки внешней системой. Для продакшена можно выключить, добавив `AUTH_DISABLED=0` и нужные пароли/секрет.
- SQLite хранится локально в томе - для одного инстанса достаточно. Если планируется масштабирование >1 реплики - потребуется внешняя БД.
- Entrypoint в образе корректно настраивает права на `/app/data`.
- Контейнер запускается от непривилегированного пользователя `node`.
